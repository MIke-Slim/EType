# 系统输入法句子入口修复（2026-10-04）

用户在聊天输入框中仍看到了旧的绿色单词候选窗。此前的文件安装检查和直接加载 DLL 的组件测试，未证明当前聊天进程已更新。

只读检查进程中映射的 PE 头确认：ChatGPT 进程保留旧的 EType DLL 映像，磁盘文件已经更新。运行中宿主不会因为覆盖 DLL 文件自动替换映像。

本次开发试用新增系统入口 **EType 单词与句子**，使用独立 CLSID、语言配置和安装目录。最初保留了旧入口；用户随后确认整合为一个入口，旧入口的 32/64 位注册已取消，原文件和注册信息备份仍保留。选择统一入口后，Ctrl+Shift+空格切换单词和句子模式；句子模式空格用于分词，Enter 翻译/确认中文，Ctrl+Enter 输出英文；候选窗左上角显示当前模式。此按键映射是用户在入口统一后确认的修订。

另外发现 `--activate` 只启用了启动程序所在进程的配置。启动操作已改为启用当前 Windows 会话的配置。数值和适用范围核对了 [微软 ActivateProfile 文档](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfinputprocessorprofilemgr-activateprofile) 与 [微软 SDK 头文件](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/msctf.h)。组件测试仍使用进程内激活，避免测试影响整个桌面。

验证包括：88 项核心检查、32/64 位各 158 项 TSF 集成检查、已安装原生句子组件中的英文编辑和翻译检查、独立进程通过 Windows 注册表创建正确 COM 服务、会话配置激活、当前 ChatGPT 进程确实映射了新目录的 DLL。完整键盘输入与中文确认在用户聊天框中的表现仍需用户实际反馈，不能用组件测试替代。

`build/sentence-profile-install-result.json` 记录开发试用安装路径；`build/registered-profile-session.json` 记录注册和会话激活结果；`build/registered-sentence-ui.json.sentences.json` 记录实际组件句子测试。

首次统一入口后的验证：32/64 位各 165 项 TSF 检查通过，覆盖 Ctrl+Shift+空格从单词切到句子、当时的 Ctrl+Enter 翻译，再切回单词并选择「河岸」。Windows 枚举结果是统一入口 1 个、旧入口 0 个；开始菜单和桌面启动入口指向统一版本。记录见 `build/profiles-after-unification.json`、`build/unified-mode-tests-x64.txt` 和 `build/unified-mode-tests-x86.txt`。后续 Enter 映射修订的检查见 `build/enter-mode-tests-*.txt` 和 `build/enter-sentence-ui.json.sentences.json`。

取消统一入口时，在试用目录运行 `uninstall.ps1 -Quiet`（会请求管理员权限）。此操作取消该入口注册，保留试用文件和个人偏好。原单词版已取消注册；如需恢复，可按 `build/unified-profile-backup-*/legacy-registration.json` 记录的原 DLL 路径重新注册。未生成 EXE 安装包。
